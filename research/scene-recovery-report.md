# 场景与阶段恢复：历史恢复后的方案判断

更新：2026-10-13。结论：**已有较完整的场景和部分 checkpoint 实现，但长任务的完整分阶段物理重建尚未解决。** Cooking 学习实验不替代机器人场景、状态恢复或正式 benchmark 的验收。

## 本次恢复了什么

仅通过用户给出的 Anygent 只读接口，先查七个会话状态（全部结束，无排队），再分次读取每个会话最近 850 条可见消息，共 5,950 条；细读五条关键工具消息。不是读取了所有早期历史。每个会话的消息范围、数量和最后回复摘要保存在 `history_recovery.json`；原始历史和访问凭据留在私有临时缓存，不发布。

末段状态：17 号采集保留 B G4 总门 FAIL，单路径见证不升级为 release；A 站转向原位四瓶与旧机位；C-21b 的过程航点门有修改、终态与接触门保留；B 站逆序出炉仍有力上限中止；R5 网页现场复核通过但回执缺失；最终 A 四瓶 demo 检查通过，材质覆盖与未入库均被更正披露。最后的“是否采集完”工具查询退出 144，不能把它当成采集完成证据。本次直接检查 NAS，确认 4×5 路视频实际存在。

原资产没有丢失：NAS 保存了 layout v4 房间 / 仪器 / 机器人、五个工作流、checkpoint 实现、多机源码快照、子操作库、原轨迹和新旧渲染。新网页只复制少量展示资产；没有覆盖任何原版本或重写旧实验。

## 据此修订方案

第一层是场景重建与可执行子操作，恢复原来更成熟的实验室场景，保留多机位和资产版本；第二层是阶段连续性，必须独立验收；第三层才是 ICL / 蒸馏学习。现有学习诊断只支持更会利用已获得的信息，不能绕过第二层后直接声称长任务 Robot RSI。

最小验收先选一个已完成的物理任务，在取出后、释放后、再抓后保存三个边界：关掉原进程，用相同完整模型与资产重建，加载状态，只执行剩余动作；与不中断原轨迹比较所有物体、关节、速度、控制器、任务图、历史和终局结果。运动学支撑路径单列，绝不替代纯物理抓持。每个边界先测恢复后第一帧，再测一段固定续跑；失败必须给首个不同字段和时间。

对阶段内部高速运动先保持“不支持”，不要默默清零速度后继续。阶段边界若采用静止协议，应在保存时核对速度，而不是仅用文字称其静止。完整随机状态和任务图的恢复、稳定全场景以及跨进程覆盖属于下一次实现与实验的明确缺口。

Cooking / task-inference 学习实验继续保留其独立进度；优先补强学生访问状态监督和已有强方法对照。场景恢复不产生新的学习成功率，学习成功率也不证明状态恢复。
